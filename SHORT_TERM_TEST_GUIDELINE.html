Short-Term Test Guideline

Puppy App Quick Trial Test

Use this guide to test the compressed local study schedule. Right now the app is configured so that 1 study day = 60 real minutes in local PostgreSQL mode.

Current local setting: backend/.env contains PUPPY_STUDY_DAY_MINUTES=60. That means you can move through many of the 24 study days within one real day.

What this test is for

  • Verify that a participant can complete Day 1, then unlock Day 2 one hour later.
  • Verify that the app blocks repeat submissions within the same study block.
  • Verify that later study days load new assigned trials correctly.
  • Verify that recovery codes and participant restore still work.

Before you start

Need running

  • Rancher Desktop or Docker engine
  • Local PostgreSQL container
  • Node backend on port 3001

Need ready

  • An active trial order in /admin
  • A private/incognito browser window
  • A place to save the participant recovery code

Step 1 — Start the local test environment

  1. Open a terminal in the project root.
  2. Start the database:
docker compose up -d
docker compose ps
  1. Start the app:
npm run dev
  1. Check health at http://localhost:3001/api/health.
  2. Open http://localhost:3001/admin and confirm a trial-order set is active.

Step 2 — Start a participant test

  1. Open a private/incognito browser window.
  2. Go to http://localhost:3001/?backend=postgres.
  3. Create a new synthetic participant.
  4. Save the recovery code shown by the app.
  5. Complete the full visit for the current study day.
After you submit, that participant is locked for the current 60-minute study block.

Step 3 — Verify the lock behavior

  1. Refresh the participant page right after completion.
  2. Confirm the app shows the locked/completed state.
  3. Confirm you cannot submit another response in the same hour block.
If you want to repeat Day 1 immediately, create a brand-new participant in a fresh incognito window.

Step 4 — Verify next-day unlock

  1. Wait until 60 minutes have passed since that participant enrolled.
  2. Reopen the app with the same participant or restore it using the recovery code.
  3. Confirm the next study day is now available.
  4. Complete that new study day and confirm it saves successfully.
The study day changes based on elapsed time since enrollment, not midnight, when using this local quick-test mode.

Suggested one-day test plan

Time Action What to verify
Hour 0 Create participant and complete Day 1 Response saves, participant locks
Hour 1 Return and complete Day 2 New trial loads, save succeeds
Hour 2 Restore participant with recovery code Recovery flow still works
Hour 3+ Repeat with same participant Each new block unlocks exactly one new study day

Optional database check

  1. Open a second terminal.
  2. Run:
npm run db:studio
  1. Inspect Participant and DailyResponse.
  2. Confirm each completed study block creates one saved response for the expected studyDay.

If you want it faster

Edit backend/.env and change:

PUPPY_STUDY_DAY_MINUTES=60

Examples:

  • 30 → one study day every 30 minutes
  • 15 → one study day every 15 minutes
  • 1440 → normal one-day schedule
Restart npm run dev after changing the value so the backend picks up the new schedule.
